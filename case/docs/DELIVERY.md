## 3. 根因分析：1400 条里几乎没有一条是"布线质量差"

### 3.1 579 条是幽灵违规（工具注入的假规则）
MCP router DSL 向板子注入了 **379 条 `copilot_router_*` 网络规则**（例：某网络被要求 `spacing = 0.59843mm`），板子按自己从未要求过的规则被判违规。
→ 用 `overwriteNetRules()` 全部复位为 `default` 后，**1361 → 21**。其中 769 条纯属虚构。

### 3.2 真违规的真凶是 **EasyEDA 的 SES 导入器忽略 SES 线宽**
导入器改用**板上 net rule 的 Track 宽度**建线，导致：
- `PGND` 线宽被放大 **6 倍**（0.2553 → 1.5494 mm）
- `+5V` 4 倍、`VCC` 3 倍、`GND` 2 倍

线一胖，Freerouting 原本留的 0.153mm 间隙就被吃光。
**反查铁证**：某对线在 FR 侧 `0.3863 − 0.2001 = 0.186mm` 合格，导入成 0.254mm 后变成 `0.132mm` 不合格。

**修复**：`restore_widths.py` 按「层 + 端点」把 1733/1789 条线映射回 SES 真值（先投票求全局平移 `dx=0, dy=−7.24mm`）→ **594 → 68 → 1**。
**结论：Freerouting 布出来的铜从第一天起就是 6mil 合规的。** 我们追了一整晚的其实是两个工具链的 bug。

### 3.3 最后 1 条 0.9µm 超差
`VCC` 水平线与 `$1N3685` 短斜段中心线距 0.4064mm，铜间隙 0.1511mm（差 0.9µm）。
**修复**：把 `$1N3685` 短斜段线宽 10.05 → 7.88 mil（`eda.pcb_PrimitiveLine.modify(id,{lineWidth})`）→ 间隙 0.1787mm ✅

## 4. 四条关键工程结论（用血换来的，务必保留）

1. **新增铜之后必须做两步后处理，否则 DRC 会撒谎：**
   ```
   落铜 → 逐 pour 实例 rebuildCopperRegion() → startCalculatingRatline() + 等 8s → DRC
   ```
   - 漏掉 `rebuildCopperRegion()` → 新铜压在未重铺的铺铜上 → **假短路**（实测一次报出 25 条 `Copper Region(Filled) to Via 0.00mil`）
   - 漏掉 ratline 重算 → 新建内层/底层铜被判**悬空线**（实测 PWM_LU 的 4 条悬空线重算后直接归 0）
   - 注意：`rebuildCopperRegion()` 是 **pour 实例**方法，不能用类调用（类调用返回 HTTP 500）

2. **相邻两网各有规则时，DRC 取更严格者** → **per-net 放宽在数学上不可能生效**。
   实验：给 5 个 BGA 网设 0.1mm 规则后，与 `default(6mil)` 的邻网之间仍报 `req = 6.0mil`。
   因 `GND` 遍布全板，放宽它 ≈ 放宽全板 → 最终口径是**全局 6mil、零例外**。

3. **内层腿尽量用单段直线**：多段首尾相接会被判悬空（对照实验：单段 0 条悬空 vs 多段 4 条悬空）。
   注：`eda.pcb_PrimitivePolyline` 只能画板框/机械图形，**不能画铜**。

4. **Freerouting 把铜摆在了 BGA 球的正下方/正旁边**：球焊盘只存在于 TOP 层，内层上不违规，所以 FR 合法地把走线贴着球走了过去，一直没暴露。
   而 **0.4mm 过孔比 0.249mm 的球大 0.0755mm**，一插进去就撞。

### 6.1 第一类：U6 球阵逃逸（6 个网络）—— 需搬开球旁的 FR 走线

数学结论（**与过孔尺寸无关**）：
```
搭接约束：过孔圆心距球心 ≤ r_via + 0.1245mm
6mil 约束：过孔圆心距障碍 ≥ d_obs + r_via + 0.152mm
```

| B 的全部失败（**偏心过孔**，其位置无焊盘） | ❌ 无焊盘 | **失败** |

> **理论：EasyEDA 的连通图只认"焊盘参与的连接"。裸 走线↔过孔（该处没有焊盘）不会被织入连通图。**

**这条理论对实现路径的直接推论：**
- 过孔**必须落在焊盘上**（via-in-pad），并且内层腿的端点**也要落在该过孔中心**（=焊盘位置）→ 三重重叠 → 一定能连（v1 已验证）
- 一旦过孔被迫**偏心到没有焊盘的位置**，连接就断 → 这正是 B 那 4 颗球（以及 `U1` 的 0.4mm pitch 焊盘，其上放不下 0.4mm 过孔）死锁的真正原因
- 因此 **`U1` 侧（`PWM×5`/`PT1`）和 `U6` 的 4 颗堵死球，在当前工具链下无法用"偏心过孔 + 换层"解决**
  —— 这不是几何问题（几何已证明可行），是**工具限制**

### 两条未验证的路子（各约 5 分钟，用来直接证伪/证实上面这条理论）
```
a) 改变创建顺序：先建线 → 再建过孔（当前工具是同批次创建）
b) 落铜后 保存并重开文档（MCP: sync_current_document；或 save + 关标签页 + 重开）再跑 DRC
   —— 重开文档会强制重建整张连通图，这正是 `save()` 做不到的
```
**建议先验 (a)**：如果"先线后孔"能让偏心过孔也连通，则 `PWM×5` + `PT1` 共 12 条连接错误一次性可解。
**再验 (b)**：若连通图确实只在文档加载时才完整重建，那所有增量落铜都必须"落一批 → 重开 → 复核"。

## 11. 【重要】Freerouting DSN 层名缺陷 —— 已定位并修复（可复现）

### 症状
用 `eda.pcb_ManufactureData.getDsnFile()` 导出当前板 DSN 后跑 Freerouting，日志出现 3139 条 WARN：
```
Shape.read_circle_scope: layer with name '15' not found in layer structure.
Wiring: wire has no shape at 'GND'
```
→ 板上 **319 条内层走线被 FR 全部丢弃**（Inner1 294 + Inner2 25），FR 以为内层是空板。

### 根因
EasyEDA 导出的 DSN 里，**层结构用名字声明，但走线的 path 用数字引用**：
```
(layer TopLayer (type signal)) ... (layer Inner2 (type signal))     ← 声明用名字

(wire(path 1  10.05 707.7 2168.9 ...))   894 条   ← 引用用数字
(wire(path 2  10.05 ...))                356 条
(wire(path 15 10.05 ...))                294 条   ← FR 认不出，整条丢弃
(wire(path 16 10.05 ...))                 25 条   ← 同上
```
FR 能靠序号猜出 `1→TopLayer`、`2→BottomLayer`，**但 15/16 猜不出来**。

这也解释了 README 里长期没查透的那条坑："手工 DSN 丢失线形（658 wire has no shape）"——
**之前每一轮 Freerouting 都是在"内层数据残缺"的 DSN 上跑的。**

### 修复（已验证）
```python
s = re.sub(r'\(path 15(?=\s)', '(path Inner1',      s)   # 294 处
s = re.sub(r'\(path 16(?=\s)', '(path Inner2',      s)   #  25 处
s = re.sub(r'\(path 1(?=\s)',  '(path TopLayer',    s)   # 894 处
s = re.sub(r'\(path 2(?=\s)',  '(path BottomLayer', s)   # 356 处
```
**实测效果：3139 WARN → 2 WARN**，`wire has no shape` 与 `layer not found` 双双归零。
修复后的 DSN：`tools/tourbox7.dsn`。

### 但仍有一个未解问题（接手人注意）
即使层名修好，FR 仍报 **374 个未布通项**（真值只有 13 个网），原因是：
> **DSN 格式无法表达那 4 块"已填充铺铜"。** 板上 GND(124 焊盘) 和 VCC 的连接主要靠铺铜完成，
> FR 看不到铺铜 → 以为这些引脚全都没连 → 想用走线连起来 → 报出 374 个未布通项，
> 并出现 `BasicBoard.normalizeTraces: reached 2000 iterations ... geometry may be oscillating` 警告。

**所以"用 FR 补布剩余 13 个网"必须先解决铺铜表达问题**（或改用"只导出未布通网络 + 既有铜作为障碍"的子集 DSN）。

## 14. 【重要教训】反复调用 rebuildCopperRegion() 会损毁铺铜

**事故经过**：在做偏心过孔实验期间，我每轮落铜后都调用 `pour.rebuildCopperRegion()` 重铺。
连续调用数次之后，`eda.pcb_PrimitivePour.getAll()` **返回 0 个铺铜** —— 4 块铺铜被删除了，
板子指纹从 `4 铺铜(已填充 4)` 变成 `0 铺铜(已填充 0)`，Connection Error 从 27 涨到 35。

**恢复方法（已验证）**：
1. `mcp__easyeda__restore_checkpoint_for_current_page(pg9027w9cwtzoeqa)` → 铺铜对象回来了，但**填充仍是 0**
2. 用 `eda.pcb_PrimitivePour.get(id)` **逐个**取实例，再调 `p.rebuildCopperRegion()`，每次之间等 4 秒
3. 全部调完后等 10 秒 → `save()` → 复核指纹应恢复 `4 铺铜(已填充 4)`

**铁律（新增）**：`rebuildCopperRegion()` **一轮操作最多调一次**，不要在同一批里反复调用。
落铜 → 重铺一次 → ratline → DRC，这一轮就结束；下一批重新开始。

**最终恢复状态（已复核）**：`1829 线 / 199 过孔 / 4 铺铜(已填充 4) / 166 元件`，
Clearance 0 / Connection 27，且**连接错误清单与基线逐条一致**（13 个网 26 个对象）。
检查点 `aq10y32l8s51ogq7`。

## 15. 偏心过孔连通性实验：结论与"测试设计"的教训

做了 4 轮受控实验（2 种创建顺序 × 4 个位置 × TOP/INNER_2 两层），结果**无法判定**。原因不是实验失败，是**测试设计有缺陷**：

> 我构造的测试结构（via1 在焊盘上 + 一条走线 + via2 在空处）**本来就没有连到网络的另一端**，
> 所以 DRC 报这些对象"disconnected"是**完全正确的行为** —— 无法区分
> "过孔没和走线建立连接"与"这个铜岛本来就还没接通"。

**已确证的（可用）**：
| 画法 | 结果 |
|---|---|
| 两个焊盘中心各放 via + 一条走线（`SW_BK`） | **Connection 27 → 24** ✅ 该网彻底连通 |

**未确证（需要更好的测试才能判定）**：过孔**偏心到焊盘之外**时，走线能否与它建立连通。

**下次要做这个实验，必须满足三个条件**：
1. **判据只能是"网络连接错误数下降"**（必须真正把那个网连通），不能看"有没有报悬空"
2. **目标几何必须事前证明合法**（净距 ≥6mil），否则会被撞铜污染
3. **自由空间搜索必须覆盖全部图元类型**：`Line` + `Via` + `Pad` + **`Fill`** + **`Region`** + **`Pour`**
   —— 之前我只查了前三种，所以连续两次把"裸过孔"放进了看不见的 `PGND`/`GND_BK` 铜里

**这个实验为什么值得做**：若成立，`PWM×5` + `PT1` + `SW_BK` 共 14 条连接错误可以一次性解决。
**若最终判定不成立**，则 `U1`(0.4mm pitch) / `U4`(0.5mm pitch) 的逃逸只能靠**设计级改法** ——
即把 `U4` 挪到 `U1` 旁边，让 5 条 PWM 变成 3–5mm 的**焊盘直连短走线（完全不需要过孔）**。

## 16. ⭐⭐【已证实】偏心过孔 + 走线 可以建立连通 —— 这是解开剩余 13 个网的钥匙

### 决定性实验（判据：连接错误数下降）
`SW_BK`（`R9_1` @334.66,1465 ↔ `U4_5` @400.48,1555.52）：
```
via1 落在 R9_1 焊盘中心
via2 落在焊盘外的空位 (397, 1528)      ← 偏心过孔，无焊盘
BOTTOM 长线  via1 → via2
TOP 短线    via2 → U4_5 焊盘

结果：Connection Error  27 → 24   ✅✅✅  SW_BK 彻底连通
      Clearance Error    0 → 5    （via2 离一片 CPL 铜还差 1.5mil，纯几何问题）
```
**净分变差，已按纪律回滚**（板子回到 `Clearance 0 / Connection 27`，指纹 1829 线/199 孔/4 铺铜已填充）。

### 为什么前 12 轮都判定"偏心过孔不通"
1. **判据错了**：前面几轮看的是"有没有报 `/ Track` 悬空"。但测试结构**本来就没连到网络另一端**，
   所以 DRC 报"孤立岛"是**正确行为**，与"过孔能否连通"无关。
   → **正确判据只有一条：网络连接错误数是否下降。**
2. **障碍模型不全**：`rebuildCopperRegion()` 之后我从 `Line/Via/Pad` 三类查空间，
   连续两次把裸过孔放进了看不见的铜里。
   → **必须覆盖全部六类**：`Line` + `Via` + `Pad` + `Fill` + `Poured` + `Region`。
3. **筛选算法错了**：用"端点到中心距离"筛，**漏掉了穿行而过的长线**。
   → **必须用真正的点到线段距离。**

### 🔍 由此查出剩余网络难以逃逸的真正原因（此前完全不知道）
用点到线段距离重查 `U4_5` 周围，发现 Freerouting 在 **INNER_1 上铺了三条横贯全宽的长线**：

| 网络 | 层 | 起点 | 终点 | 距 `U4_5` 焊盘中心 |
|---|---|---|---|---|
| **`ADC0.1`** | 15 | (671.9, 1551.6) | (297.6, 1551.6) | **3.92 mil** ← 就在那排焊盘正下方 |
| `ADC1.1` | 15 | (266.1, 1583.4) | (438.4, 1583.4) | 27.88 mil |
| `ADC2.1` | 15 | (264.9, 1618.9) | (426.7, 1618.9) | 63.38 mil |

**通孔贯穿所有层 → 这三条线在 `y∈[1551,1619]` 形成一道"过孔禁区"**，
所以任何放在 `U4` 那排焊盘附近的过孔都会撞上去。**过孔必须放到禁区之外**，
再用一小段 TOP 短线接回焊盘 —— 而这条短线-过孔的连接，**上面已验证可行**。

### 结论：剩余 13 个网现在是"路径规划问题"，不再是"能不能做"的问题
正确的优化器应满足：
1. 障碍模型：六类图元全收 + 点到线段距离（不是端点距离）
2. 过孔候选：焊盘内（via-in-pad）**和**焊盘外的合法空位都要搜
3. 过孔位判据：到最近异网铜的**边到边**距离 ≥ `6mil + via_r`
4. 落铜后：重建铺铜一次 → ratline +8s → DRC ≥2pass → **只降不升才保留**（判据=连接错误数）
5. 短接链段数不设硬上限（"偏心过孔可行"已证实，不需要用长蛇形去躲）

|---|---|---|---|
| `7f3b757ab423edf0` | TOP 5mil 短桩（球心 → 孔） | — | — |
