## 3. 回退过的一批（重要教训）

第一轮曾对 `SW_BK`(7 段) 与 `$1N19139`(5 段, 0.191mm) 落铜，DRC 复核后 **Clearance 0 → 18 条**
（`SW_BK` 对 `FB_BK` 5.34–5.90mil，`$1N19139` 对 `VBUS` 5.91–5.95mil），随即
`--rollback-nets 'SW_BK,$1N19139'` 删除 13 段，回到 Clearance 0。

根因：栅格化距离变换会**高估**净距（斜向铜最多高估 `res×0.707` ≈ 0.0144mm@0.02mm 栅格），
导致规划器把 5.8mil 当成 6.0mil。已在 `stitch_connections.py` 中把 `res*0.75` 计入阈值，
并增加“用真实几何复算、低于 6mil+0.2mil 一律弃用”的硬门槛（本次即靠它拦下 `SW_BK`）。

## 5. 建议（需要你拍板）

1. **BGA 逃逸（8 个网络的核心障碍）**：唯一可行解是 **via-in-pad**，但板上既有过孔规格 0.61/0.305mm
   在 0.5mm pitch 下对邻球只剩 **0.07mm**（不满足 6mil，也不满足 0.1mm）；
   若改用 **Ø0.40mm / 钻孔 0.20mm**，到邻球净距 **0.175mm(6.9mil)** ✅ 可行。
   这属于改制作规格，**需你确认是否允许**（JLCPCB 等常规工艺 0.2mm 钻孔可做）。
2. **`SW_BK` / `GND_BK`**：允许 0.22–0.24mm 补线即可连通（净距 6.0–6.3mil，贴线但达标）；
   若要更稳，需要挪 `FB_BK` 那条 45° 斜线（本次未动他人铜）。
3. **`PWM_*` / `PT1` 长距离**：建议由路由器（Freerouting/DNS 重跑）在**包含这些网**的前提下重布，
   或人工布线；局部加铜无法解决 20–32mm 的穿越问题。
4. 若客户接受把这几条网的规则放宽到 0.13–0.15mm，我可以按“贴线但不低于放宽值”的名义复跑补通。

## B. 板上 DRC 规则（`get_pcb_drc_rules` 实测）

```
viaDiameter: min 0.5 / pref 0.61 mm      ← 批准的 0.40mm via 违反此规则
viaDrill   : min 0.3 / pref 0.305 mm     ← 批准的 0.20mm 钻孔违反此规则
clearance  : track-track 0.152, track-pad 0.152, track-via 0.152,
             track-copper 0.254, track-board 0.3, **track-hole 0.175 mm**
```

**结论：规则是全局的，没有"逃逸区分区放宽"**。
批准的 4mil 逃逸区放宽在**几何上**可做，但 DRC 仍按 6mil/0.175mm 判 → 必然报违规。

## C. PWM_LU / PWM_U：**几何上通了**（这是本轮最大进展）

* 单层无解（bottleneck 在 (30.868,57.350)，被 I2CSCL/SCLK 铜夹到 0.100mm=3.94mil），
  但按你提示的 **"径向外逃 + 第一时间打孔换层"** 后成立：
  * U1_26 焊盘径向外逃 0.9–2.1mm → 打 0.5/0.3mm 过孔（**符合板上规则**）→ INNER_2 走 22.8mm
    → 目标端过孔 → U4_28 短接；
  * 在**严格 6mil、不放松**的前提下找到路径（`_st25_multi.py`，pinch 0.291mm ≥ 需求 0.279mm）；
  * 落铜后 U4_27 侧的 3.9–4.5mil 违规消失了（那一版是我把逃逸区放宽到 0.095mm 导致的，已改正）。
* **唯一剩余障碍**：INNER_2 上一个**无网络名的 `pcb_PrimitiveFill`（id `e602`，layer=12 多层）**
  在 (21.34,53.04) 处被我的线穿过（d=0.0，3 条 Clearance）。
  我的障碍模型只覆盖 line/pad/via，**没有覆盖 Fill/Poured/Region** → 已把 dump 扩展成会读取它们
  （`extra` 已能取到 6 个对象：1×Fill + 4×Poured(=4 个铺铜) + 1×Region），
  但 `getState_ComplexPolygon()` 返回的是 **dict**（`{...}`）而我的解析器按 list 处理 → 还没吃进去。
  **修法明确**：`_complex_to_polys()` 里加一句 `if isinstance(cp, dict): cp = cp.get('complexPolygon')`，即可把 e602/Region 变成障碍，PWM_LU/U 就能干净落地。

## D. BGA（U6）via-in-pad：卡在规则，不卡在几何

* 0.4/0.2mm via 在 U6 球阵：到邻球 **0.1755mm(6.9mil)** ≥ track-hole 0.175 ✅ 几何成立（与你的复算一致）；
* 但 DRC 报 **`Physical Error / Via Size`**（viaDiameter min 0.5、viaDrill min 0.3）→ 需改规则；
* 用**合规的 0.5/0.3mm** via 则半径 0.25 > 到邻球 0.175 → 不成立。
  → **BGA 逃逸必须在"改 min via 规则"和"放弃"之间二选一**。

## E. 一次失败教训（已回滚）

同一轮里把 PWM_LU 与 PWM_U 一起规划、再一起落铜 → 两条 INNER_2 走线互相压线
（86/90 条 Clearance 都是 PWM_U↔PWM_LU）。**必须"规划一条→落铜→重读板子→再规划下一条"**，
`stitch_connections.py` 每次 `--apply` 都会重新 dump 板子，天然支持串行；不要用一次 `--plans-file` 塞多条同区网络。

## F. 下一步（按优先级）


1. **改全局**（或把球阵附近所有相关网络都指向 0.1mm 规则）——等价于全局放宽，与原意冲突；
